# 用户声音挖掘模板

## 目标

不是写综述，是提炼**可指导产品决策**的洞察。每条洞察要能回答："所以我们产品该多做什么、少做什么？"

## 搜索来源

按优先级：

1. **竞品评论区**：App Store、Google Play、Chrome Web Store、Product Hunt、G2、知乎商品回答
2. **技术社区**：Reddit（相关 subreddit）、Hacker News、V2EX、即刻、少数派
3. **中文社区**：知乎、小红书、微博、B站评论区
4. **GitHub Issues / Discussions**：开源竞品的 issue 区是金矿，用户会把痛点写得非常具体

## 搜索词模板

- `<竞品名> 缺点 / 吐槽 / 垃圾 / 替代`
- `有没有类似 <竞品名> 但是 <期望改进点> 的`
- `我想要一个能 ___ 的工具`
- `how do you handle <问题> without <竞品>`
- `<领域> 工具 推荐 2025`（看最新对比帖）

## 提炼方法

把搜到的帖子按主题归类，而不是逐条罗列。重点找：

- **反复出现的抱怨**：3 个以上独立来源提到同一个痛点 → 高优先级机会
- **用户自发夸的点**：用户愿意为什么掏钱、为什么留下来
- ** workaround**：用户现在在用什么凑合方案 → 那就是我们的直接竞争对手
- **付费意愿信号**："要是有 X 我愿意付 $Y/月"

## 输出格式

```markdown
# 用户声音 · <产品名>

## 机会点（用户在抱怨什么）
### 1. <痛点标题>
- 证据：
  - <原帖摘要>（<链接>）
  - <原帖摘要>（<链接>）
- 对我们的启示：<我们应该/不应该做什么>

### 2. ...

## 价值点（用户在夸什么、愿意为什么付钱）
- ...

## 空白点（没人做好的）
- ...

## 用户原话摘录（备查）
- "..." — <来源链接>

## 本轮盲区
- 未覆盖的渠道：...
- 证据最薄的结论：...（要加固该去哪补）
```

## 纪律

- 严格遵守 `anti-hallucination.md`：引用的每个帖子/评论必须本轮真实打开过，转述与原帖不符 = 违规
- **每条洞察至少 2 个独立来源**才算数，单条轶事标为"待验证"
- 不要编评论。搜不到就写"本轮未覆盖，建议后续补充 X 社区"
- 区分"用户说要的"和"用户真正需要的"——用户常会提错误的解决方案，记录时区分他们的**抱怨**和他们的**建议**
- 文档末尾必写"本轮盲区"：哪些渠道没覆盖、哪些结论证据最薄、要加固该去哪补
