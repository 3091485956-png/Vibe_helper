# 竞品与开源调研模板

## 搜索策略

不要只搜一次。至少做这几组搜索：

1. **直接关键词**：产品名 + 英文同义词 + 功能词组合
2. **GitHub**：
   - `general_search` 搜 `site:github.com <功能关键词>`
   - 浏览器打开 GitHub 搜索页，按 stars 排序，翻前 2–3 页
   - 看 awesome 列表（awesome-<领域>）
3. **商业产品**：Product Hunt、AlternativeTo（输入已知竞品找替代品）、小众软件、知乎"有哪些 X 类工具"
4. **间接竞品**：解决同一问题但方式不同的（例：做待办的竞品不只是其他待办 App，也包括日历、邮件 flag、Notion database）

每个真有参考价值的项目/产品，**实际打开它的主页/README/官网**看一眼，不要只看搜索摘要。

链接与数据纪律见 `anti-hallucination.md`：只有本轮真实打开过的链接才能进报告，stars / 最近 commit 当场核对，推断显式标注。

## 🔶 对标选择与用户确认

报告写完 ≠ 调研结束。文档末尾追加三节：

### 参照竞品总表

本轮**实际打开看过**的所有竞品/项目，一行一个：

| 竞品 | 链接 | 一句话定位 | 是否推荐重点对标 |
|---|---|---|---|

### 重点对标推荐

| 竞品 | 推荐理由（用户重叠 / 形态最接近 / 最值得借鉴） | 建议拿它对标什么 |
|---|---|---|---|

不推荐重点对标的也列出来，写明原因（停止维护 / 用户群不同 / 形态差太远）。

### 确认对标集合（用户选择后填写）

- 用户确认的对标竞品：...
- 用户补充的竞品：...（补查后同样填进总表）
- 说明：Stage 4 评论挖掘、Stage 5 功能对比、Stage 6 差异化定位只针对这个集合展开

给用户的话术与选择点规则见 SKILL.md Stage 3：必须给名单、推荐、理由、备选，用户增删或说"你定"。
