# 状态卡（00-状态.md）· 组装规则与版本纪律

状态卡是全流程的**滚动主上下文**：后期阶段以它为锚、按需回查具体文档小节，而不是每次全文重读所有文档。它一份干三件事：**问卷纪要确认**（出生）、**后期上下文组装**（长大）、**交接首材料**（最终形态）。新会话或中途进入时，先读它即可接上进度。它本身就是"一页看懂"的决策面板雏形——各编号文档第一屏的决策面板是同一思路的推广（双阅读模式见 `anti-hallucination.md`）。

## 诞生与长大

| 卡版本 | 时机 | 新增/更新内容 |
|---|---|---|
| v1 | Stage 1 出口 ⛔ | 定位、目标用户、功能清单（原始）、关键约束、成功标准、存疑项、**AI 轨道判定结论**（含判定依据）、**决策模式**（自主/委托） |
| v2 | Stage 2 Brief 确认 | 明确不做（边界）、非功能需求、**能力边界（AI 轨道）**、委托代定项计数 |
| v3 | Stage 4 决策门通过后（主组装） | 确认对标集合、需求真伪初判、机会点 top、待核实提示 |
| v4 | Stage 5 范围确认 | Must 清单（带稳定 ID 与类型 常规/AI）、Won't、RICE 顺序 |
| v5 | Stage 6–7 框架与原型确认 | 最薄一刀、选型要点、**评测方案要点（AI 轨道：环节/通过线/冒烟子集）** |

- **Stage 1 出口 ⛔**：v1 组装好展示给用户——"这是我对问卷的记录：有没有记错的、漏的？"用户同意才继续。**快速档**：v1 与 Brief 确认门合并为一次停顿。这次确认的是**事实记录**；Brief 门确认的是**理解与取舍**，不是重复检查。
- 此后每个 ⛔ 门确认，**同一步**内刷新状态卡，不新增停顿。
- **单点/中途进入**：开工前先读 00——缺失而已有 ≥2 份文档 → 先组装；组装清单版本落后于文档版本（过期）→ 先重组装，再干活。

## 状态卡模板

```markdown
> 📌 版本 v<N> · <日期> · 组装自: <01-问卷@v1, 02-brief@v2 …> · 变更: <一行>

# 状态卡 · <产品名>

## 定位一句话
<产品名> 是给 <目标用户> 在 <场景> 下解决 <问题> 的 <形态>。

## 当前阶段
已更新至: Stage <N> · <阶段名>

## 决策模式
自主 / 委托（委托时：代定项按 [B/C·代定] 留痕，劝退门结论必须有用户原话）

## AI 轨道判定
AI 轨道 / 非 AI 轨道（依据：把 AI 拿掉，产品剩 <…>；01-问卷@vN）

## 确认对标集合
<竞品 A、竞品 B>（03@vN 确认）

## Must 清单（稳定 ID）
- M-F1 <一句话>（05@vN）
- M-F2 …

## Won't（本期不做）
- <X>（一句话原因）

## 能力边界（AI 轨道）
- 适用域 / 水平线 / 不保证（02-brief@vN；水平线以 08 评测数据为准）

## 关键约束
- 平台 / 技术栈 / 时间 / 登录要求 …

## 最薄一刀
<一句话>

## 阶段结论（每阶段 ≤3 条）
- 调研: <…>（03@vN）
- 用户声音: <真伪初判 …>（04@vN）

## 开放问题 / 存疑
- <…>
```

组装清单（组装自）只列到当前为止已存在的文档，**用完整文件名（不带 .md）**：`01-问卷@v1、02-brief@v2`。v1 时通常只有 `01-问卷@v1`。**稳定 ID（M-F1…）在 v4 首次分配**：写 05 时给每条 Must 编号，此后 05/06/07 引用功能一律带 ID，编号不再变更。

## 版本规则（所有编号文档 + 状态卡）

1. 首次落盘 = v1，必须带版本头：`> 📌 版本 v1 · <日期> · 变更: 初稿`；05 及之后的文档另加 `基于 00-状态@vN`
2. 任何**已确认**文档被修改 = 版本 +1，并在变更处追加一行说明（一行以内，不写小作文）
3. 修改源文档后，**同一步**刷新 00-状态.md——不许出现"03 已 v2、组装清单还写着 03@v1"的中间态
4. **过期判据**：00 组装清单里某文档的版本 ≠ 该文档当前版本头 → 状态卡过期，必须重组装后才能继续
5. 版本头保持两行以内——规则一旦变重就会被跳过；validate.sh 强制检查

## 一致性审查 checklist（三个时点：组装时 / Stage 7 确认前 / Stage 8 交接前）

- [ ] 05 的每条 Must 都有来源（02 功能清单 / 03 竞品 / 04 用户声音），无凭空新增
- [ ] 06 页面清单 ↔ 05 Must 双向覆盖：每个 Must 有页面承载，每个页面都能指到 Must
- [ ] 07 选型不违反 02 约束（平台、登录、技术栈偏好）
- [ ] 最薄一刀对应某条具体 Must，能端到端走通
- [ ] Won't 清单里的功能没有在任何后续文档"复活"
- [ ] **AI 轨道：每条 AI 类 Must 都有 08-评测方案的评测引用；02 能力边界与 08 通过线一致（边界不是写出来的，是测出来的）**
- [ ] **委托模式：代定决策均有 [B/C·代定] 标注；劝退门结论附用户原话**
- [ ] 功能 ID（M-F*）全程一致；产品名、术语各文档一致
- [ ] 00 组装清单版本 == 各文档当前版本头（无过期）

发现冲突：**先改正文档（bump 版本 + 变更行），再重组装状态卡**。只改状态卡把矛盾盖住 = 违规。

## 与档位的关系

- 快速档：v1 与 Brief 门合并；状态卡可精简为 5 行（定位 / Must / Won't / 约束 / 存疑），版本纪律不减免
- 标准档：用完整模板
- 深度档：可加"机会点 top"与"风险"小节，仍控制在一页内
