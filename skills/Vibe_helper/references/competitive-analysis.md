# 竞品与开源调研模板

## 深度档位

开始前先确认档位（用户不选 → 标准）：

| 档位 | 竞品数量 | 范围 |
|---|---|---|
| 快速 | 5 个左右 | GitHub 按 stars top 3 + 商业产品 2，够做"有没有人做过"的判断 |
| 标准（默认） | 10–15 个 | 直接竞品 + 开源项目 + 间接竞品，多关键词交叉 |
| 深度 | 20+ | 标准范围 + 间接竞品专章 + 中英文双语检索 + 商业模式/定价对比 |

## 搜索策略

不要只搜一次。至少做这几组搜索：

1. **直接关键词**：产品名 + 英文同义词 + 功能词组合
2. **GitHub**：
   - 搜 `site:github.com <功能关键词>`
   - 浏览器打开 GitHub 搜索页，按 stars 排序，翻前 2–3 页
   - 看 awesome 列表（awesome-<领域>）
3. **商业产品**：Product Hunt、AlternativeTo（输入已知竞品找替代品）、小众软件、知乎"有哪些 X 类工具"
4. **间接竞品**：解决同一问题但方式不同的（例：做待办的竞品不只是其他待办 App，也包括日历、邮件 flag、Notion database）

**工具策略**：用当前环境可用的搜索/浏览工具——浏览器类工具优先（能实际打开 GitHub、Product Hunt、Reddit、HN 等站点浏览最好），没有就用宿主的通用搜索工具。不要假设特定工具存在，有什么用什么。

每个真有参考价值的项目/产品，**实际打开它的主页/README/官网**看一眼，不要只看搜索摘要。

链接与数据纪律见 `anti-hallucination.md`：只有本轮真实打开过的链接才能进报告，stars / 最近 commit 当场核对，每条论断标 A（有证据）/ B（证据+推理链）/ C（模型推测，进待核实清单）。

## 好 / 坏记录对照

❌ 坏例：

> Notion — 功能全面的笔记软件，很受欢迎，生态很好。

（零决策价值：没有数据来源、没有对我们的意义、没有可执行结论。）

✅ 好例：

> Notion — [A：官网 + App Store 评论区] 类型：商业；定位：all-in-one 工作区；数据：App Store 效率类 Top 20（本轮当场核对）。对我们的意义：它的"重、慢、打开要等"是评论区高频抱怨 [A：评论区 3 条原话附后]（后续用户声音阶段重点验证），若我们做"秒开单页笔记"正对此痛点。可借鉴：block 编辑器的数据结构设计。短板：离线几乎不可用 [A：官网 FAQ 明确标注]。

（有证据等级、有当场核对的数据、有"所以我们怎么办"。）
