# 交付前 Checklist（开发收尾必过）

**用途**：写完代码、准备宣布"做完了"之前，逐条过一遍。
任何一条不过，就不算交付。不要自己放水——这是 vibe coding 项目 90% 翻车的地方。

## 1. 验收对照（来自 05-需求分层.md）
- [ ] 跑过机器自检：`bash <本skill目录>/scripts/validate.sh ./<产品名> --expect 交付包`，全部通过
- [ ] 交接前一致性 checklist（`context-assembly.md`）已跑：00 组装清单与各文档版本一致、功能 ID（M-F*）一致
- [ ] 每个 Must have 用户故事的**每个验收场景（Given/When/Then）**都逐条验证过
- [ ] **AI 轨道：08-评测方案整集跑完、每个环节达通过线**（附通过率记录）；期望列无"AI 无痕代答"残留——预填格仍标"默认答案（C 级）"的，交付话术里要明说
- [ ] 输出了一份验收对照表：每个场景 → 实际结果（通过/未通过 + 证据）
- [ ] 没有偷偷加 Must 以外的功能（发现一条就移到 `backlog.md`）

## 2. 状态与边界
- [ ] **空状态**：第一次打开、没有任何数据时，页面显示什么？不是白屏、不是报错
- [ ] **错误状态**：网络失败、输入非法、第三方 API 报错时，用户能看到人话提示，不是 stack trace
- [ ] **加载中**：耗时操作有 loading 反馈，不是按钮点了没反应
- [ ] **边界输入**：空输入、超长输入、特殊字符、并发操作——至少想过，能 graceful 处理

## 3. 安全与数据
- [ ] **没有硬编码密钥**：API key / secret 全部走环境变量或配置文件，且 .gitignore 了
- [ ] **输入校验**：前端和后端都校验，不信前端
- [ ] **认证/授权**（如有登录）：路由保护、token 过期处理、管理员权限——至少想过
- [ ] **数据库访问控制**（如用 Supabase/Firebase）：RLS 策略开了，不是裸奔

## 4. 能真的给别人用
- [ ] **部署方式**：有一键部署链接（Vercel/Cloudflare Pages/Netlify）或明确的本地启动步骤
- [ ] **环境依赖写清**：README 或启动说明里写了需要哪些环境变量、怎么申请
- [ ] **最小 README**：这个产品是干嘛的、怎么跑、怎么测一次核心流程——三句话以内能说清

## 5. 视觉与原型一致
- [ ] 页面布局、配色、组件对齐 `prototypes/` 里的静态原型
- [ ] 没有自由发挥加原型里没有的页面或模块

## 6. 收尾
- [ ] `backlog.md` 里记下了开发过程中临时想到但没做的功能
- [ ] **AI 轨道：`badcase台账.md` 已随包创建**（空表 + 归因分诊表 + 回灌规则，模板见 `references/badcase-ledger.md`），并告知使用方"每个已修 badcase 必须回灌成评测用例"
- [ ] **委托模式：所有 [B/C·代定] 决策在交付话术里汇总明示**——用户签字的是"哪些是我定的、哪些是 AI 替我定的"，不是一锅端
- [ ] 如果发现需求/原型和实际冲突，回头更新了对应的 md 文件，而不是在代码里偷偷改

---

## 给用户的交付话术

> 产品做完了。对照验收标准：
> - 【列每个验收场景（Given/When/Then）的通过情况】
> - 【AI 轨道】评测结果：评测集 N 例，各环节通过率【…】，通过线【…】
> - 【委托模式】以下决策是 AI 替你定的（[B/C·代定] 汇总），随时一句话推翻：【…】
>
> 你可以从 【链接/路径】 打开试用。
> 已知没做的（进 backlog）：【列 backlog 前几条】
>
> 试试在【空状态/错误场景】下操作一下，看有没有崩。
