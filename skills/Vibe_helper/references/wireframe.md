# 静态原型图规范

产出语言跟随用户语言：原型页面文案用用户的语言，目录与文件结构保持模板原样。

## 目的

在写正式代码之前，用**可点击的高保真静态 HTML** 让用户看到产品长什么样、点起来什么感觉，提前发现"理解错了"的地方。这一步改 10 分钟，胜过后面返工 10 小时。

## 深度档位

| 档位 | 页面数 | 范围 |
|---|---|---|
| 快速 | 2 | 入口页加核心功能页，够确认方向 |
| 标准，默认 | 3–6 | 入口、核心主页、1–2 个关键流程页、空状态或结果页 |
| 深度 | 5–8 | 标准范围，加移动端窄屏适配，加空状态与错误状态各一页 |

## 产出位置

```
./<产品名>/prototypes/
├── index.html          # 入口，落地页或主界面
├── login.html          # 如有
├── main.html           # 核心功能主页
├── flow-step-2.html    # 关键流程的下一步
├── result.html         # 结果页
└── assets/
    └── style.css       # 共享样式，也可内联
```

## 画哪些页面

**只画 Must have 涉及的页面**。

1. 入口页：落地页或首次打开
2. 核心功能主页
3. 1–2 个关键流程步骤页：点击、填表、结果
4. 空状态：第一次用，什么都没有
5. 结果或输出页。AI 轨道时此页必须体现边界文案，含限制提示、置信话术、降级文案

Should 与 Could 的页面**不画**，避免浪费，也避免诱导范围蔓延。

## 保真度要求

- **不是线框图**：不要灰白方块。要有真实配色、真实间距、真实字体、真实图标
- **用真实文案占位**：不要用"Lorem ipsum"。写成用户真会看到的句子
- **mock 数据写死**：列表里放 3–5 条像样的假数据，让人一眼看懂产品干啥
- **页面之间能点**：按钮真的能跳到对应静态页，不要全是死按钮
- **边界看得见，AI 轨道必做**：输入限制提示如"支持 500–5000 字"；AI 结果页的置信与免责话术如"摘要可能遗漏细节"；失败降级文案如"这段处理不了，试试分段"。以上真实写在页面上。**用户不读文档，只看屏幕；边界躺在 02-brief 里等于没有**
- **响应式基本可用**：至少在桌面宽度下正常；移动端产品要补窄屏效果
- **不接后端、不写真实业务逻辑**：纯展示

## 风格参考

- 参考竞品调研里用户觉得"好看、顺手"的产品，借鉴其布局节奏
- 配色克制：一个主色加一个强调色加中性灰，不要花
- 留白要够，不要塞满

## 给用户看时的话术

> 静态原型我画好了，在 `prototypes/` 目录下，从 `index.html` 打开就能点。
>
> 请你：
> 1. 在浏览器里把能点的地方都点一遍
> 2. 看看布局、文案、流程是不是你想象中的样子
> 3. 告诉我：哪里要改、哪里不对、哪里缺东西、哪里多余
>
> 我改到你说 OK 为止，然后再开始写真产品。

## 反馈循环

- 用户提的每一条都改到原型里
- 改完重新让用户过目
- **用户明确说"可以了"或"就这样"之前，不许进入开发阶段**
- 如果用户说"差不多就行直接做吧"，也要把已提的修改全部落完再走
