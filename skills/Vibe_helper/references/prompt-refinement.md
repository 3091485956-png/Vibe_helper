# 产品 Brief 模板

把访谈的口语化回答，重写成一份工程师可直接阅读的 Brief。目标：**消除所有模糊词**。

## 写作要求

- 不要写"赋能、抓手、闭环"这类黑话
- 每个论断尽量具体：不说"提升效率"，说"把原本 3 步的操作压到 1 步"
- 模糊词必须替换或删除："类似 XX"、"等等"、"一些功能"、"好用"
- 明确写出**不做什么**，和做什么同等重要

## 好 / 坏对照

❌ 坏例（节选）：

> 面向年轻人的高效笔记工具，功能丰富，体验流畅，支持多端同步等，让大家记录更轻松。

（"年轻人"多年轻？"高效"怎么算？"功能丰富"是哪些？"等"是什么？读完不知道要做什么。）

✅ 好例（节选）：

> 面向备考考研的学生（22–26 岁，手机 + 图书馆电脑双端），解决"纸质笔记无法搜索、复习时翻不到"的问题。核心场景：晚自习拍照归档当天笔记 → 按科目/日期打标签 → 复习时用关键词搜出原页。本期不做：协作编辑、语音转文字（进二期）。

（用户是谁、痛在哪、第一次打开做什么、边界在哪，全部可执行。）

## Brief 模板

```markdown
# 产品 Brief · <产品名>

## 1. 定位
<产品名> 是一个 <形态> 产品，帮助 <目标用户> 在 <场景> 下完成 <核心任务>，
相比现有方案的核心差异是 <一句话>。

## 2. 目标用户
- 主要用户：<画像，含职业/水平/设备>
- 次要用户：<如有>
- 不服务谁：<明确排除>

## 3. 痛点
- 用户现在怎么解决：<现状>
- 现状的问题：<具体痛点 1、2、3>
- 我们的解法：<一句话>

## 4. 核心场景
1. <场景 A：谁，在什么情况下，做什么，期待什么结果>
2. <场景 B>

## 5. 功能清单（原始，未排序）
- F1: ...
- F2: ...

## 6. 非功能需求
- 性能：<首屏速度 / 并发 / 数据量预期>
- 平台：<Web / iOS / Android / 桌面…>
- 合规：<隐私、数据存储、登录要求>
- 其他约束：

## 7. 明确不做（本期边界）
- 不做 X
- 不做 Y

## 8. 成功指标
- MVP 完成后，用 <指标> 判断是否成了
```

## 给用户确认时的话术

> 我根据你的回答整理了一份产品 Brief，你过目一下：
>
> 【贴出 Brief】
>
> 有没有哪里理解错了、漏掉了，或者想加/想删的？
> 没有问题的话回复"OK"，我就开始做竞品调研。
