# 用户声音挖掘模板

## 目标

不是写综述，是提炼**可指导产品决策**的洞察。每条洞察要能回答："所以我们产品该多做什么、少做什么？"

## 深度档位

| 档位 | 渠道数 | 范围 |
|---|---|---|
| 快速 | 2 | 竞品评论区 + 1 个社区，够做"需求真伪初判" |
| 标准（默认） | 4 | 评论区 + 技术社区 + 中文社区 + GitHub Issues |
| 深度 | 6+ | 标准范围 + 中英文社区都扫 + 时间线对比（抱怨是否长期存在） |

## 搜索来源

按优先级：

1. **竞品评论区**：App Store、Google Play、Chrome Web Store、Product Hunt、G2、知乎商品回答
2. **技术社区**：Reddit（相关 subreddit）、Hacker News、V2EX、即刻、少数派
3. **中文社区**：知乎、小红书、微博、B站评论区
4. **GitHub Issues / Discussions**：开源竞品的 issue 区是金矿，用户会把痛点写得非常具体

## 搜索词模板

- `<竞品名> 缺点 / 吐槽 / 垃圾 / 替代`
- `有没有类似 <竞品名> 但是 <期望改进点> 的`
- `我想要一个能 ___ 的工具`
- `how do you handle <问题> without <竞品>`
- `<领域> 工具 推荐 2026`（看最新对比帖）

## 提炼方法：看行为证据，不看口头意愿

Mom Test 的原则同样适用于"读帖子"：**用户做了什么（用 workaround、付费、花时间绕过）比用户说了什么（"希望有个 X"）可信得多**。

把搜到的帖子按主题归类，而不是逐条罗列。重点找：

- **反复出现的抱怨**：3 个以上独立来源提到同一个痛点 → 高优先级机会
- **用户自发夸的点**：用户愿意为什么掏钱、为什么留下来
- **workaround**：用户现在在用什么凑合方案 → 那就是我们的直接竞争对手。有人在付钱/花时间凑合 = 需求为真 [实证]；只有人嘴上说想要、没人在凑合 = 需求存疑 [假设]
- **付费意愿信号**："要是有 X 我愿意付 $Y/月"

## 好 / 坏洞察对照

❌ 坏例：

> 用户普遍对现有工具不满意，希望有更好的产品。

（"普遍"是多少？来源在哪？对产品决策没有任何指示。）

✅ 好例：

> **机会点：截图多了找不到**
> - 证据：Reddit r/productivity 两个帖子 + V2EX 一个帖子，均在抱怨"截图堆满桌面、要用时找不到" [实证 ×3]
> - 行为证据：有人专门装了 Eagle/ Hazel 用规则自动归档 [实证 ×1]，说明痛到愿意花时间凑合
> - 对我们的启示：MVP 必须把"找回"做到 10 秒内，而不是做更漂亮的截图编辑——用户在骂"找不到"，没人骂"编辑器丑"

## 输出格式

```markdown
# 用户声音 · <产品名>

## 机会点（用户在抱怨什么）
### 1. <痛点标题>
- 证据：
  - <原帖摘要>（<链接>）
  - <原帖摘要>（<链接>）
- 行为证据：<有没有人在付费/用 workaround/花时间绕过>
- 对我们的启示：<我们应该/不应该做什么>

### 2. ...

## 价值点（用户在夸什么、愿意为什么付钱）
- ...

## 空白点（没人做好的）
- ...

## 需求真伪初判
- 独立来源数 / 是否存在行为证据 → 初判：真需求 / 存疑 / 假需求（附证据等级）

## 用户原话摘录（备查）
- "..." — <来源链接>

## 本轮盲区
- 未覆盖的渠道：...
- 证据最薄的结论：...（要加固该去哪补）
```

## 纪律

- 严格遵守 `anti-hallucination.md`：引用的每个帖子/评论必须本轮真实打开过，转述与原帖不符 = 违规
- **每条洞察至少 2 个独立来源**才算数，单条轶事标为"待验证"
- 不要编评论。搜不到就写"本轮未覆盖，建议后续补充 X 社区"
- 区分"用户说要的"和"用户真正需要的"——用户常会提错误的解决方案，记录时区分他们的**抱怨**和他们的**建议**
- 文档末尾必写"本轮盲区"：哪些渠道没覆盖、哪些结论证据最薄、要加固该去哪补
