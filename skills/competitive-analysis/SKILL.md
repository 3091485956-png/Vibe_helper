# Competitive Analysis — 竞品与开源调研

回答三个问题：**这个赛道里有什么？它们做得怎么样？我们的位置在哪？**产出一份每个论断都有证据等级、每个链接都真实打开过的竞品分析报告。

在 Vibe_helper 全流程中对应 Stage 3；单独使用时本 skill 独立完成。

## 输入

- 最好有 `02-brief.md`（或一段产品描述：做什么/给谁/核心功能）；已有 `00-状态.md` 时先读它的定位与约束（避免重问用户）
- 什么都没有 → 先问 3 个问题（产品一句话定位、目标用户、核心功能），**不要求完整 Brief**，拿到就能开工
- 用户点名要查的竞品 → 优先深查，其余自己补

## 深度档位（开场确认，默认标准）

| 档位 | 竞品数 | 范围 |
|---|---|---|
| 快速 | ~5 | GitHub top 3 + 商业 2，够回答"有没有人做过" |
| 标准 | 10–15 | 直接竞品 + 开源项目 + 间接竞品 |
| 深度 | 20+ | 标准范围 + 间接竞品专章 + 中英双语检索 + 定价对比 |

## 步骤

1. **多组搜索**：策略见 `references/competitive-analysis.md`——直接关键词 / GitHub 按-stars-浏览 / Product Hunt、AlternativeTo / awesome 列表 / 间接竞品（解决同一问题的不同路径）。**不要只搜一次**
2. **每个竞品实际打开**主页/README/官网看，当场核对 stars、最近 commit。记录字段与好/坏记录对照见同文件
3. **写报告** `03-竞品分析.md`：概览 → 直接竞品 → 开源参考 → 间接竞品 → 对本产品的启发（可借用 / 要避的坑 / 差异化位置）→ **本轮盲区**
4. **🔶 对标选择点**：报告落盘 ≠ 调研结束。向用户汇报：①参照竞品总表（真实打开过的）②重点对标推荐 2–3 个（理由只能是：用户重叠最高 / 形态最接近 / 最值得借鉴）+ 不推荐及原因 ③问用户："你有没有要补的竞品？想换重点对标的直接说；不想管就说'你定'。"
5. 用户增删 → 补查新增竞品、更新报告再确认一轮；确认后把最终集合写进"确认对标集合"小节——**这是后续功能对比和差异化的锚**

## 零幻觉纪律

全文遵守 `references/anti-hallucination.md`：每条论断标 [实证/推断/假设]；链接必须本轮真实打开；数字当场核对，取不到写"未获取"；禁止自我评价词；末尾强制"本轮盲区"。编造链接/数据 = 该段作废重做。

## Common Pitfalls

- **搜索摘要当看过**：没打开页面的竞品不许进"参照竞品总表"
- **stars/维护状态凭印象填**：当场核对，取不到就写"未获取"
- **堆数量显得勤奋**：30 个只看过标题的竞品不如 10 个真打开看透的
- **跳过对标选择点**：报告落盘就直接结束——没有"确认对标集合"等于没交货
- **只查直接竞品**：用户现在拿什么凑合（Excel、微信群、人肉）往往才是真对手
- **只搜中文或只搜英文**：两边生态不同，交叉才全（深度档强制双语）
- **修改已确认报告不 bump 版本**：补查/修改 03 必须版本 +1 并加变更行（版本头规则见报告模板顶部）

## 输出物

- `03-竞品分析.md`（带版本头；含"确认对标集合"小节，🔶 用户拍板后）
