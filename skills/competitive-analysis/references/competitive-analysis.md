# 竞品与开源调研模板

产出语言跟随用户语言：03-竞品分析.md 正文用用户的语言，文件名与小节标题保持模板原样。

**结构金标准**：`references/report-examples/金标准-竞品分析.md`（用户提供）。报告骨架、每竞品五维分析、横向对比表、生态位地图、三分法结论、组合式定位建议，对照它写。注意：金标准范例未带 A/B/C 标注与待核实清单，我们的产出这两样必须带，不得以"像金标准"为由省略——诚实机制谁都不豁免。

## 深度档位

开始前先确认档位，用户不选则用标准。**档位管竞品数与检索广度，不管报告骨架**：快速档也要有横向对比、生态位地图与三分法结论，只是每个竞品的五维写得更短。

| 档位 | 竞品数量 | 范围 |
|---|---|---|
| 快速 | 5 个左右 | GitHub 按 stars 取 top 3 加商业产品 2，够做"有没有人做过"的判断；五维各 1–2 句 |
| 标准，默认 | 10–15 个 | 直接竞品、开源项目加间接竞品，多关键词交叉；五维完整，优劣各 ≥3 条 |
| 深度 | 20+ | 标准范围加间接竞品专章、中英文双语检索、商业模式与定价对比；另加时间线对比看竞品是否腐朽 |

## 搜索策略

不要只搜一次。至少做这几组搜索：

1. **直接关键词**：产品名加英文同义词加功能词组合
2. **GitHub**：
   - 搜 `site:github.com <功能关键词>`
   - 浏览器打开 GitHub 搜索页，按 stars 排序，翻前 2–3 页
   - 看 awesome 列表，即 awesome-<领域>
3. **商业产品**：Product Hunt、AlternativeTo 输入已知竞品找替代品、小众软件、知乎"有哪些 X 类工具"
4. **间接竞品**：解决同一问题但方式不同。例：做待办的竞品不只是其他待办 App，也包括日历、邮件 flag、Notion database

**工具策略**：用当前环境可用的搜索与浏览工具。浏览器类工具优先，能实际打开 GitHub、Product Hunt、Reddit、HN 等站点浏览最好；没有就用宿主的通用搜索工具。不要假设特定工具存在，有什么用什么。

每个真有参考价值的项目或产品，**实际打开它的主页、README、官网**看一眼，不要只看搜索摘要。

链接与数据纪律见 `anti-hallucination.md`：只有本轮真实打开过的链接才能进报告，stars 与最近 commit 当场核对，每条论断标 A 即有证据、B 即证据加推理链、C 即模型推测并进待核实清单。

## 每个竞品：速查行 + 五维分析

每个竞品先给一行速查（沿用记录字段），再按**统一五维**展开论述。五维顺序固定，所有竞品一致，读者才能横向对照：

**速查行**：名称｜链接｜类型（开源/商业/内部工具/个人项目）｜stars｜最近 commit｜是否仍在维护

**五维正文**：

1. **项目简介**：项目是什么、谁维护、规模量级（stars、收录数、用户量）。2–4 句
2. **项目链接**：逐行列出。仓库、在线文档、论文、安装方式，有都列，全部本轮真实打开
3. **技术框架**：技术栈与架构设计。能从 README、package.json、仓库结构看出来的都写
4. **竞争优势**：≥3 条，每条是**完整论点**不是短语。"第 N，<论点>。<展开一两句>。"附证据等级
5. **劣势与局限**：≥3 条，同上格式。劣势即我们的机会，每条尽量点出"所以我们有机会做什么"

快速档放宽为：五维各 1–2 句，优劣各 ≥2 条。

### 好 / 坏论点对照

坏例：

> 竞争优势：社区活跃；文档好。

短语不是论点。活跃到什么程度？文档好在哪？读者无法据此做任何决策。

好例（摘自金标准）：

> 第四，社区认可度高。超过 6 万星标和多语言翻译说明其已形成广泛的使用群体。

有数量、有判据、有结论。我们的产出再补上证据等级即完整：`[A：GitHub stars 本轮当场核对]`。

### 竞品速查好 / 坏记录对照

坏例：

> Notion：功能全面的笔记软件，很受欢迎，生态很好。

零决策价值：没有数据来源、没有对我们的意义、没有可执行结论。

好例：

> Notion [A：官网 + App Store 评论区]。类型：商业；定位：all-in-one 工作区；数据：App Store 效率类 Top 20，本轮当场核对。对我们的意义：它的"重、慢、打开要等"是评论区高频抱怨 [A：评论区 3 条原话附后]，后续用户声音阶段重点验证；若我们做"秒开单页笔记"正对此痛点。可借鉴：block 编辑器的数据结构设计。短板：离线几乎不可用 [A：官网 FAQ 明确标注]。

有证据等级、有当场核对的数据、有"所以我们怎么办"。

## 横向对比与生态位地图

全部竞品写完后，必须产出两样东西，读者才能从"一堆项目"看到"一张地图"：

1. **横向对比表**：跨竞品统一维度一张表。固定列：项目名称、项目类型、核心技术栈、目标用户、<本领域的深度维度，如"复现深度"、"协作能力"、部署方式>、开源协议。每个竞品一行，每格一个短语
2. **生态位地图**：表后一段文字，回答两个问题——每个竞品处于生态的哪一层（发现层/实现层/工程层/评估层…按本领域划分）；**没有任何竞品覆盖的空隙在哪**。这句空隙判断就是差异化定位的证据基础，写不出空隙说明要么调研不够，要么赛道真的挤（这本身就是关键发现，喂 Stage 4 劝退门）

## 三分法结论：可模仿、可优化与非必要

报告结论必须三分，对应读者关心的三个问题：学什么、改什么、不学什么。

1. **值得模仿**：每条 = 具体做法 + 来源竞品 + 对我们的意义。具体到"它的 X 机制可以直接搬"，不写"学习其优秀设计"
2. **可以优化的环节**：竞品做得差、用户在骂、我们能做好的。每条点出改进方向，喂 04 用户声音阶段重点验证
3. **非必要或可延后**：竞品有、但**我们明确不学**的东西，每条附理由（成本高、生态位不同、依赖未成熟技术…）。这一节是调研侧的 Won't have，防止调研诱发 scope creep——看了一堆竞品就想什么都做，是最常见的调研后遗症。此处判"非必要"的功能，后续想翻身必须走 backlog 流程

对照金标准"四、可模仿、可优化与不必要的部分"：三分各 4–5 条、每条带来源与理由的密度，是标准档的成色。

## 结论与定位建议

最后一节给出可拍板的结论，三件套：

1. **赛道诊断**：一句话说清格局（碎片化/拥挤/空白/腐朽），按路线或类型归并
2. **组合式定位建议**："X+Y"式一句话，如金标准的"教学复现+工程辅助"。借谁的什么、组合成什么
3. **初期聚焦与远期探索分层**：初期只做什么范围，什么方向留远期。推荐依赖 C 级证据时必须声明，此为信心洗白禁令

## 选择点 · 对标选择与用户确认

报告写完不等于调研结束。文档末尾追加三节：

### 参照竞品总表

本轮**实际打开看过**的所有竞品与项目，一行一个：

| 竞品 | 链接 | 一句话定位 | 是否推荐重点对标 |
|---|---|---|---|

### 重点对标推荐

| 竞品 | 推荐理由：用户重叠 / 形态最接近 / 最值得借鉴 | 建议拿它对标什么 |
|---|---|---|

不推荐重点对标的也列出来，写明原因，如停止维护、用户群不同、形态差太远。

### 确认对标集合，用户选择后填写

- 用户确认的对标竞品：...
- 用户补充的竞品：...。补查后同样填进总表
- 说明：后续的用户声音挖掘、功能对比、差异化定位**只针对这个集合**展开，不再自由发挥

给用户的话术与选择点规则见 SKILL.md：必须给名单、推荐、理由、备选，用户增删或说"你定"。
